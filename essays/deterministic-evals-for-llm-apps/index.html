测教育问答助手与 AI 生图时，为什么单靠字词匹配拦不住逻辑颠倒

复盘我们在测试问答助手与 AI 生图功能时遇到的提示词退化问题，以及我在开源实现 EvalGate 后通过自查暴露出的 3 个判错 bug 和取舍。

一、测 AI 功能遇到的第一个难题：接口返回 200，回答却开始偏离规则

以前测常规业务接口，输入参数固定，返回的字段值也是固定的。但在测试教育类问答助手和 AI 生图功能时，哪怕只是为了优化语气微调了一句系统提示词，原本答得准的课本知识点也可能开始超纲编造，甚至把教务请假扣课时的比例答错；手工抽查十几个问题看着没毛病，一上边缘场景就露馅。

二、做成个人工具 EvalGate 后，自查出的三个判错问题

为了把这些检查固化下来，我把脱敏场景写成了开源工具 EvalGate。但在拿边界用例反测自己写的代码时，一下子暴露出三个典型问题：

  • 字词重合度看不出逻辑颠倒：把“开课前 2 小时以上免费、不足 2 小时扣 0.5 课时”完全说反，因为词都一样，字词重合度依然打出 0.909 的高分。最后补了可选的 LLM 裁判模式（llm_judge）专门抓逻辑矛盾，未配置裁判时明确标为跳过，绝不默默算作通过。
  • 拒绝关键词会掩盖泄露：如果回答里先说“虽然我不能保证准确”，后面却照样把系统提示词吐了出来，单靠匹配“不能/抱歉”会误判为安全。改成先查敏感信息与指令泄露，再查是否明确拒绝。
  • Python 里布尔值会被当成整数：JSON 里返回 {"score": true} 时 isinstance(True, int) 为真，漏过了类型校验，已显式排除 bool。

三、现在的边界与运行示例

确定性断言负责每次 CI 零成本初筛，LLM 裁判负责按需复核逻辑矛盾；同时如实记录了词库覆盖有限、JSON Schema 仅为子集等已知局限。

python -m evalgate run --config examples/edu_assistant_eval.json --html report.html
